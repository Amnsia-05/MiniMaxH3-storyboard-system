从小说到 H3 成片：六步流程

这一版是按实际拍摄反馈重写的：固定 3 镜已废除，换成「长镜头叙述 + 短镜头快切」双模式； 提示词从"省着写"改成"填满 5000–7000 字符"；全本小说只拆大纲，章节内容逐章喂、逐章细做。

六步 画风已锁定：3D 次世代写实 每条提示词 5000–7000 字符 2026-08-30 v3

00流程合约（开工前先读，三条不许破）

这套流程的核心是「谁在什么时机给什么」。AI 与你的分工用合约锁死，避免一上来把全本脚本写完、白耗字数还丢失细节。

合约一：全本进来，只出大纲

你丢完整的小说给 AI 时，AI 只做 Step 2（拆大纲）：集级大纲 + 段级钩子 + 角色表 + 场景表。 不出分镜、不出提示词、不写台词。

理由：大纲阶段对节奏的判断是全局的，脚本阶段对细节的发挥是局部的。 混在一起做，要么细节被压缩比牺牲（v2 版踩过的坑），要么全局节奏被局部细节带偏。

合约二：章节内容逐章喂，逐章细做

你按大纲指定的顺序，一次给一章（或一集对应的原文）；AI 对这一章做 Step 3–5： 长短镜头判定 → 分镜 → 5000–7000 字符的 H3 提示词。做完一章验收一章，再进下一章。

合约三：每条 15s 提示词 5000–7000 字符

字符口径：每条 15 秒 clip 的提示词独立计数，含空格与换行（Python len() 口径）。 低于 5000 = 细节不够，要补；高于 7000 = 超上限，必砍。这件事由 Step 5 的预算表保证。

01Step 1 · 定画风（全剧一次定死）

画风决定参考图提示词、H3 视觉描述、角色一致性。漏了会在铺开后整批返工。本剧已确认，写死如下，全剧不换；换画风 = 重新出全套参考图。

已锁定 3D 次世代写实动漫 2026-08-30 确认

画风串（逐字复用，一字不改）

next-gen 3D anime rendering, thick painted CG texture, delicate material rendering, visible brush strokes, soft volumetric light, cinematic depth of field, ray tracing, rim lighting, 8K, ultra detailed, clear readable silhouette, limited palette of three colours, hand-painted feel

负面补充（塑料感三件套——本画风最高发翻车）

plastic texture, 3d render look, excessive bloom
【正向补丁】hand-painted feel（已含在画风串末尾）

使用规则

  • 画风串放在每条提示词第一行，与参考图生图提示词用同一套词——图与文字说同一件事
  • 换题材只换服装 / 场景 token，画风串一个字不改
  • 光位串独立于画风串，按场景写，同一场景内跨 clip 原样复述（匹配剪辑锚点）

02Step 2 · 拆大纲（全本进来，只出大纲）

对应合约一。这一步的产出是后面所有章节工作的施工图，但不做任何脚本级细节。

做什么 通读全本 → 四张表 s h3-novel-split

输入 / 输出

输入

完整小说全文。AI 通读一遍，标记情节线、人物关系、爽点 / 情绪转折位置。

明确不做

分镜、提示词、台词、运镜——全都不做。做了就是违约，返工。

产出：四张表

表字段
集级大纲集号 / 叙事块数 / 集长（= 块数 × 15 秒）/ 本集核心冲突 / 卡点类型 / 出场人物
段级钩子每集内逐段（15s 一段）列一行：段落任务 + 结尾钩子（动作 / 台词 / 揭示 / 视线 / 倒计时五选一）
角色表主角 / 配角 / 路人分层；每人登记：身份、可辨识独有特征、固定穿搭、行为锚点（细节留给章节工作）
场景表场景名 / 光位描述 / 出场集数（出图后立刻把光位记回本表——色彩锚点唯一来源）
集长算法：叙事块数 × 15。不按字数硬套。 例：原文 12 个叙事块 → 180 秒/集。压缩比推断值误差可达 ±50%，必须先做样片实测再重排全剧。
大纲里同时排好「逐章喂」的顺序：按叙事价值排序（最有戏的章节先做样片）， 每章标注对应的集号 / 段号，你按单喂即可。

03Step 3 · 长短镜头判定（逐章内容进来后第一步）

你喂来一章内容后，AI 先把它切成「事件清单」，逐个事件判定用长镜头还是短镜头。这一步定错，Step 4 全白做。

做什么 事件清单 + 长短判定 s h3-action-body

一句话判据

这个动作的「过程」是不是看点？

是 → 长镜头事件：过程即剧情（怎么救的、怎么对峙的、怎么拉扯的），专注动作细节分解，用长镜头叙述。
不是，只是过场 → 短镜头动作：1–2 秒交代完，绝不占长镜头。

判定表

类型典型例子拍法
长镜头事件海里救人（游近→托起→拖拽→撞礁）、追逐、对峙拉扯、长时间劳作 长镜头叙述；动作按节拍分解（then 串联，每镜 ≤3 拍，动作有终点）；一件事 15s 讲不完就 2×15s
短镜头动作开门、开窗、推门进来、站起来、坐下、转头、拿起杯子 1–2 秒短镜头（≥1.5s 硬下限），静态机位或微推，动作单一有终点；密集时用硬切串联（见 Step 4 模式 B）
插片特写手部细节、面部微表情、关键道具 2–3 秒，插进长镜头之间或之中，防止画面枯燥
边界情况怎么判：「起身走向门口开门离开」——起身 / 走 / 开门三个都是短动作， 合计 4–6 秒，可以做成 3 个短镜硬切；但如果「走」的过程中有戏（犹豫、回头、偷听）， 「走」就升格为长镜头事件。判定跟着戏剧任务走，不跟着动作字面走。

长镜头的硬规矩（动作细节怎么写才不崩）

  • 动作按节拍写：First ... then ... finally ...，每镜 ≤3 拍
  • 每个动作必须有终点（then holds / settles against / freezes on）
  • 跟拍类运镜 ≤6 秒且背景要简单；push-in 的落点设计成特写（免费的高级感）
  • 长镜头里的人物状态要写不变量（如「昏迷瘫软、双腿拖行不踩地」），防止模型自作主张

校验点

04Step 4 · 分镜编写（双模式 + 硬切）

v3 的核心改动：固定 3 镜已废除。按 Step 3 的判定结果选模式——长镜头事件用模式 A / C，短动作密集段用模式 B。

做什么 三选一：A 叙事长段 / B 快切段 / C 长镜插特写 s h3-camera-edit

模式 A · 叙事长段（一件事讲不完 → 2×15s）

适用：长镜头事件，15 秒装不下（如完整的海里救人）。两条 clip 拼成一件事，动作匹配衔接。

Clip内容衔接要点
Clip 1氛围铺垫短镜（2–4s，可无人空镜）+ 主长镜（11–12s，结尾定格在关键接触帧） Clip 1 末帧 = Clip 2 首帧（同一姿态、同一手、同一物）；三锚点对齐：同色温 / 同运动方向 / 同构图重心，用 the same ... 正向复述
Clip 2从同一接触帧续起：反应 / 后果 / 收尾（10–15s）
实例（海里救人，已实拍验证）：Clip 1 = 浪拍黑礁空镜 4s + 蒋筱筱游泳托人主长镜 11s（末帧定格右臂撞礁接触帧）； Clip 2 = 撞后伤口特写推近 8s + 僵住不松手收尾 7s。两 clip 之间动作匹配，观众读起来是连续的 30 秒。

模式 B · 快切段（短动作密集 → 5–7 镜硬切）

适用：开门、开窗、推门进来、站起、坐下这类 1–2 秒短动作连着来。15 秒做 5–7 个短镜，特殊运镜 + 硬切。

15s 切法镜数适用
3 + 3 + 3 + 3 + 35每个短动作带一点运镜（推 / 摇）
2.5 × 66均匀快切，节奏最稳
2 + 2 + 2 + 2 + 2 + 2 + 37最密；最后一镜 3s 留给收尾定格
  • 每镜 ≥1.5s 硬下限，设计值 2–3s；承载信息镜 ≥3s
  • 切动词：the camera cuts to / the shot cuts to 等，默认硬切，不做溶解
  • 每次切换必须引入新信息（主体 / 空间 / 状态 / 视角至少变一项）；只是角度微调 → 用运镜，别切
  • 快切段每镜动作必须单一——镜内只发生一件事，别把两个动作塞进 2 秒
  • 运镜可以每镜换（这正是"特殊运镜效果"的用法）：推近开门的手 → 切 → 摇过窗 → 切 → 跟人进门
快切段的一致性红利：5–7 镜在同一次请求内生成，人物一致性由同请求保证， 比拆成多条跨请求生成稳得多。快切段的合法性正来自于此。

模式 C · 长镜插特写（防止长镜头枯燥）

适用：长镜头事件，但过程偏长、需要节奏变化。主长镜 + 1–2 个 2–3s 插片特写。

15s 切法说明
主长镜 11s + 插特写 2s + 插特写 2s特写插在动作节拍之间（手部 / 表情 / 道具），切进切出都锚在动作上
主长镜 10s + 插特写 5s（push-in 落点即特写）或者不切，直接在长镜内用 push-in 把落点推成特写——零剪辑成本拿特写

模式选择决策

Step 3 的事件清单里——
├─ 有 1 个长镜头事件，15s 装不下？        → 模式 A（2×15s）
├─ 有 1 个长镜头事件，15s 装得下但偏长？  → 模式 C（长镜 + 插特写）
├─ 全是短动作、没有长事件？               → 模式 B（5–7 镜快切）
└─ 长事件 + 周围一堆短动作？              → 混合：A 或 C 为主，
   短动作压成 1–2 个短镜塞在开头 / 结尾

时间戳与切镜红线（所有模式通用）

  • 第一个镜头不加时间戳；后续镜头 At 00:SS.mmm 三位小数，严格递增且落在 15s 内
  • 每镜一个主运镜（官方术语 + 幅度 + 速度），运镜句前置；一镜最多 2 个运镜
  • 时长必须落在 4–15 秒整数（单次请求）；每镜 ≥1.5s

校验点

05Step 5 · 写 H3 提示词（5000–7000 字符 / 条）

v3 第二个核心改动：不再省着写。官方上限 7000 字符（按字符计，1 汉字 = 1 字符，不是 token）； 目标区间 5000–7000，省下的空间全部用来细致描写运镜、面部表情、动作分解、心理对白、人物对白、路人管理。

填满 ≠ 注水。反堆砌三规则：
① 每一句必须承载新信息——同义反复（把同一特征换个词再说一遍）不算细节，只占字符；
② 重复 ≠ 强调——模型不吃重复，只吃冲突；同一句复制三遍不会更稳，还会稀释关键约束；
③ 宁可 5200 字符句句有效，不要 6900 字符里一半是水。5000 是目标下限，不是硬凑指标。
低于 5000 时的补写优先级（从最有杠杆的开始）：
动作分解（把每个动作写出起点 / 路径 / 终点 / 受力） → 面部表情（把每个情绪转折写成可见肌肉序列） → 运镜落点（把每镜推 / 拉的终点写成具体画面） → 环境反应（发丝 / 衣摆 / 水花 / 光影随动作的变化） → 路人管理与状态不变量。 禁止靠复制粘贴锁定块凑字数。

字符计数（验收口径）

Python:  len(prompt_text)        # 含空格与换行，即提交全文
目标区间: 5000 ≤ len ≤ 7000
低于 5000 → 按补写优先级加细节
高于 7000 → 先砍 Constraints 里的冗余项，再砍与正向重复的描述

转官方格式（固定三字段）

integrated_multimodal_description:  逐镜头展开视觉与剧情内音频（时间戳：首镜不加，后续 At 00:SS.mmm）
overall_soundscape:                 环境音 / 物理动作音 / 画外音与对白
non_diegetic_music:                 只有观众能听到的配乐（无配乐写 N/A）
判别：画面里的人能听见 → soundscape；只有观众听得见 → non_diegetic_music。 音景里不得重复对白原文；配乐只写乐器 / 速度 / 节奏，不写抽象情绪词。

中文对照（每条提示词必附）

每条英文提示词下面附一个中文对照灰框（标注「仅供阅读，不提交」）， 逐句翻译，让你能直接审：动作写得对不对、心理有没有到位、限制词有没有踩线。复制按钮只复制英文正文。

### ⚠️ ③「备参考图」不要跳过（2026-08-30 补上的缺口）

角色卡与场景卡只规定**登记哪些字段**，但**那些参考图本身从哪来**一度没人管。
`h3-refsheet-gen` 补的正是这一环。

```
h3-character-asset（定义角色字段）
        ↓
h3-refsheet-gen（把字段变成图）   ← 三视图 / 表情集 / 场景图 / 道具图
        ↓
h3-character-asset §10（把图写进 Ref2VA 提示词）
        ↓
h3-antibug-check（检查）
```

**为什么必须做**：H3 的一致性是靠**图**锁的。
移除视觉锚定后，角色一致性从 **7.99 崩到 0.55**（arXiv 2512.16954）。
**没有参考图，锁定块描述串写得再精确也是空中楼阁。**

### ⚠️ 恋爱/情感题材：别把亲密戏整段省略（2026-08-30 补上的缺口）

早期拆解遇到原文的成人情节时，采用了「省略式」——只拍前因后果，中间空镜桥接。
**这个判断是错的**，使用者反馈"没看点了"。

**错在哪**：平台红线有三个限定词，**缺一不违规**——

| 限定词 | 反推可做什么 |
|---|---|
| **集中细致展现** | 点到即止、非连续、单镜短 |
| **以单纯感官刺激为目的** | **有叙事目的**的亲密表达可以保留 |
| **有明显性挑逗** | 含蓄、留白、靠观众脑补 |

红线只划掉了亲密维度的一小块，**剩下的一大片（张力/暧昧/推拉/克制）恰恰是恋爱剧的看点**，
而我把整个维度删掉了。

**正确做法**：保留张力、去掉露骨。核心技法——

```
拍「差一点」，不拍「已完成」
在预期高潮前切走，让观众自己脑补（脑补发生在观众脑子里，不在画面里）

改写三原则：
  拍反应，不拍行为     → 拍等待者的脸，比拍事件本身更有张力
  拍结果，不拍过程     → 两双鞋、散开的领带、天光，让观众自己推
  拍未完成，不拍已完成 → 停在"差一点"，打断即卡点
```

`h3-romance-tension` 给了六大技法的完整提示词、10 个常见情境库
（壁咚/醉酒/共伞/车内/职场/撞见/争吵/上药/重逢/吃醋）、合规判定表与跨集张力弧线。

> **一个额外收益**：这些技法天然规避 H3 的持续接触、布料动力学、长镜头漂移等硬阻断，
> 且大量使用特写——**特写比中景稳**。所以这不是"合规与好看的妥协"，是双赢。

**一条本体系特有的原则**：**图 ↔ 描述串互为镜像**。
图上有的特征，描述串里必须写；描述串里写的，图上必须有。
矛盾项必改其一——模型同时收到两路冲突信号，表现就是渐进式漂移（最难排查）。

## 最该记住的六条

1. **H3 ≠ Hailuo 2.3** —— 2.3 无音频、仅首帧、2000 字符；H3 有原生音频、FL2VA、7000 字符。别混用。
   （两份被 2.3 污染的调研底稿已加废弃声明，见下节）
2. **对白要 `<d>...</d>`，默认不加双引号** —— 双引号在 `base-en.txt` 里专属画面内可见文字。
   ⚠️ **但存在官方口径冲突**（官方直播建议相反），**默认遵守 base-en.txt**；若用直播技巧，引号只写在镜头描述里、不写进 `<d>` 内。
3. **一镜一个运镜，运镜句前置** —— 三镜共用同一术语；堆叠会被平均成漂移。
4. **每镜最短 1.5 秒**；1–2 秒衔接镜要生成 4 秒再裁（含 T2 单镜重生成）。
5. **崩了先抬采样步数到 6–8，别急着改提示词**。
6. **硬阻断项（可读文字、跨生成左右方位、180° 轴线、物理接触）改分镜绕开**，不要死磕提示词。

## ⚠️ 两处官方口径冲突（勿当定论，都已标【待验证】）

| 议题 | 官方来源 A | 官方来源 B | 当前处理 |
|---|---|---|---|
| **台词要不要加双引号** | `base-en.txt`：`<d>` 内无引号，双引号专属可见文字 | MiniMax × ComfyUI 官方直播：用引号写台词 | 默认遵守 A；用 B 时引号只写镜头描述，不进 `<d>` |
| **参考标签写法** | `ref-en.txt`：`<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>` | 官方开源公告 API 脚本：`<image_1>` / `<video_1>` / `<audio_1>` | 采用 A；同一提示词内不可混用 |

**为什么并列写在这里**：这套体系已出现 3 次"只采信单侧官方证据"的故障（2.3 当 H3、双引号、参考标签）。
**落地前先问一句：还有没有另一条官方来源说法不同？**

## 维护工具（内容有改动后跑一遍）

| 脚本 | 用途 |
|---|---|
| `make_html.py` | 从主模板重新生成 `MiniMaxH3-模板.html`。**改了主模板必须重跑** |
| `audit_rules.py` | **跨全库硬规则自查**。把硬规则写成正则，扫所有文件例句，自动区分正例/反例上下文 |

```bash
python audit_rules.py                  # 扫默认文件集（全部 skill + 主模板）
python audit_rules.py <文件1> <文件2>  # 扫指定文件
```

**为什么需要它**：本体系的一个高频故障是「**正面范例违反本文自己定的硬规则**」。
人工自查连抓两轮都漏（第二轮又出 3 处）。脚本能一次扫完，命中项再人工判定。

**扩展**：改脚本顶部 `RULES`（每条 = 名称 + 正则）与 `WHITELIST`（已知合法例外）即可加规则。

### ⚠️ 改内容时的多副本陷阱

**同一段提示词在交付物里有多份副本**：主模板正文 / `make_html.py` 的速取卡 / `make_html.py` 的工作区模板（**独立第二份字符串**）/ HTML 产物 / 各 skill。

改完必须：`全库 grep → 改所有副本 → 重建 → 再 grep 确认`。
本体系已在此栽过三次（台词双引号两轮、裸名词否定一轮）。

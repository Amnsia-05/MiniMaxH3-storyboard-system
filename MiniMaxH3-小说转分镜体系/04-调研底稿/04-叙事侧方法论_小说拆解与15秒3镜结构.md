## 1. 小说拆解为剧集

### 1.1 量化公式（核心）

设：单集时长 T（秒）、集数 M、段落时长 U=15s、每段镜数 k=3。

| 指标 | 公式 | 说明 |
|---|---|---|
| 每集段落数 | S = T ÷ 15 | 必须为整数，否则调整 T |
| 每集镜数 | N = S × 3 = T ÷ 5 | 平均镜长 5s |
| 全剧总镜数 | N_total = M × T ÷ 5 | |
| 全剧总时长 | D = M × T（秒） | |
| 每段平均信息点 | 1 个信息点 + 1 个情绪转折 | 【业界】每15–20秒一个小冲突/爽点 |
| 每段镜数 k | 默认 3；🟢 H3 允许 **2–4** | 见 §2.2；k 变化时本表 N 相应为 S×k |

**速查表（k=3）**

| 单集 T | 段落 S | 每集镜数 | 60集总镜数 | 总时长 |
|---|---|---|---|---|
| 60s | 4 | 12 | 720 | 60 min |
| 90s | 6 | 18 | 1080 | 90 min |
| 120s | 8 | 24 | 1440 | 120 min |
| 180s | 12 | 36 | 2160 | 180 min |

**小说字数 → 集数反推**

每集可容纳台词/旁白字数：`W_ep = T × V × ρ`
- V = 语速（字/秒），见 §4，AI 配音取 **4.5**
- ρ = 台词占用率，**0.70**（【业界】建议台词不超过容量 80%，留停顿与画面呼吸）

| 单集 | W_ep（ρ=0.70, V=4.5） |
|---|---|
| 60s | ≈189 字 |
| 90s | ≈284 字 |
| 120s | ≈378 字 |

集数：`M = 剧本总量 ÷ W_ep`。剧本总量与小说原文的**压缩比**【推断】：网文 100 万字 → 约 3–6 万字剧本（压缩比 3–6%），即 120s/集约 100–160 集；实操建议先按 **每 8000–12000 字原文 = 1 集（120s）** 试算，再用样片校准。此为推断值，误差可能 ±50%，**建议客户先做 3 集样片测真实压缩比**。

### 1.2 单集节奏模板（T=120s / 8 段）

【业界】单集骨架：黄金3秒钩子 → 10秒抛矛盾 → 30秒首次反转 → 中段高密度推进 → 结尾强钩子。映射到 15 秒段落【推断】：

| 段 | 时间码 | 叙事任务 | 情绪 | 备注 |
|---|---|---|---|---|
| P1 | 0–15 | 黄金3秒钩子（承接上集悬念，直接见血/见耳光/身份暴露） | 冲击 | 禁止慢开场、禁止环境铺垫 |
| P2 | 15–30 | 建矛盾：谁/在哪/遇到什么麻烦/要什么 | 紧张 | 10秒内三件事交代完 |
| P3 | 30–45 | **第一次反转/爽点**（压→爆） | 释放 | 【业界】前30秒必须给一次情绪释放 |
| P4 | 45–60 | 推进主线，埋钩子伏笔 | 缓 | 可插缓冲镜 |
| P5 | 60–75 | 矛盾升级（新对手/新证据） | 紧 | |
| P6 | 75–90 | 二次危机，主角受压 | 压 | |
| P7 | 90–105 | 高潮前夕，底牌将亮未亮 | 憋 | |
| P8 | 105–120 | **强钩子卡点**+黑屏 | 悬 | 钩子力度 > 本集所有冲突 |

90s 集（6段）：P1钩子 / P2矛盾 / P3反转 / P4-P5推进 / P6卡点。
60s 集（4段）：P1钩子+矛盾 / P2反转 / P3升级 / P4卡点。

**15秒段落的信息量共识**：【业界】短视频"一镜一信息"；【推断】15 秒段落 = **1 个叙事节拍 = 1 个信息点 或 1 个情绪转折，二者不可兼得**。若必须同段内"给信息+转情绪"，则信息用台词、转折用画面（或反之），不要都压在台词上。台词容量硬上限见 §4。

### 1.3 断章 / 卡点技巧

【业界】三类高转化结尾钩子：悬念钩、危机钩、反转钩。固定操作：卡在情绪最高点戛然而止 + 黑屏。

| 卡点类型 | 切断位置 | 视觉/听觉表现 | 下一段/下集开口 |
|---|---|---|---|
| 动作卡点 | 动作**完成前** 0.3–0.5s | 扬起未落的巴掌、将落未落的刀 | 动作完成 + 后果 |
| 台词卡点 | 关键词**之前** | "其实我早就知——"（切黑） | 承接补全 |
| 揭示卡点 | 揭示**瞬间** | 门开一线、信封撕开一角、报告单翻转 | 揭示内容全景 |
| 视线卡点 | 人物看向画外 | 瞳孔骤缩 + 画外音 | 其"所见"即下一镜 |
| 危机倒计时 | 数字归零前 | 倒计时/逼近的脚步声 | 爆点 |

**集尾 vs 段尾的区别**【推断】：集尾卡点是"硬断"（黑屏/切黑，力度最大）；15 秒段尾卡点是"软断"，靠**出镜（C 镜）**承接——即出镜本身就是微型卡点与缓冲器，它让上一段的余韵落地，同时把下一段的入口准备好。

> 🟢 修正：出镜在 v2 中为 1.5–2.5s，v3/v4 下按范式表取 **3–5s**（承载信息镜需 ≥3s）。卡点位置相应从"出镜末尾"变为"**出镜内部的最后 1–2 秒**"——即出镜前段做缓冲留白、后段落卡点。**卡点技巧本身不变，只是落点在一个更长的镜头内部。**

## 2. 15 秒 3 镜结构范式

### 2.1 "主镜 + 双衔接镜"的作用（验证客户理解）

客户的判断**基本正确**，但需补充与修正：

| # | 作用 | 判定 |
|---|---|---|
| 1 | 缝合：把独立生成的 15 秒片段拼成连续长片 | 🟢 **段内已不需要**：H3 单次请求可出 2–4 镜，三镜共享上下文、同一次推理，**段内无接缝**。此需求只剩**段与段之间** |
| 2 | 裁切对齐：把时长误差、首尾抖动放在衔接镜上 | 【推断】仍成立，但作用点移到**段间** |
| 3 | **生成质量**：主镜压到 11–12s 是质量/时长平衡点 | 🟢 **此约束消失**。多镜由时间戳切分。🔵 11s 主镜**合法**（硬下限仅 1.5s），但**不推荐**——切点密度建议约每 3 秒一切，11s 不切远低于该建议（见 §2.2） |
| 4 | 节奏呼吸阀：防止 8 段连续高密度信息造成疲劳 | 【业界】成立。**且实现方式变了**——见下 |
| 5 | **一致性锚点**：衔接镜可复用同一参考图批量生成 | 🟢 **段内已由模型架构保证**（共享上下文）；参考图锁的作用点移到**段间**与**跨集** |
| 6 | 成本：衔接镜可复用、可批量，摊薄单集成本 | 【推断】；H3 多镜一次生成 ≈ $1.95/15s（2K） |

**修正一（功能分工）**：两个衔接镜功能**不同**，应分开命名与设计——
- **入镜（A，接上段）**：确立时空、承接情绪、给出"入口"。
- **出镜（C，接下段）**：卡点、留白、交棒，是下一段的"预告片"。

**修正二（🟢 关键：主次关系不再靠时长体现）**。v2 的"11s 主镜 + 2s+2s 衔接镜"是**被生成能力逼出来的妥协**，不是叙事最优——短剧常规镜长本就是 2–5 秒，11 秒单镜偏长。H3 不支持悬殊切分后，主次关系改由三个维度承载：

| 维度 | 主镜（B） | 衔接镜（A / C） |
|---|---|---|
| **信息密度** | 承载 1 个信息点或情绪转折 | 低信息，只做进入/留白/交棒 |
| **景别** | 中近景–特写（靠近人物） | 远景/空镜/局部特写（远离或抽离） |
| **运镜** | 单一明确运镜 | 多为固定或极缓 |

> **结论**：三镜时长可完全相等（5/5/5），主次关系**不受影响**。呼吸感由"低信息密度的衔接镜内容"提供，不由"短时长"提供。

### 2.2 时间分配范式（v4 再次修订）

🟢 **H3 单次请求内镜数预算：13–15 秒 → 2–4 镜**，靠时间戳切分（`[Shot 1]` → `[Shot 2] At 00:05.000` → `[Shot 3] At 00:10.500`）。

> 🔵 **真实约束是「每镜最短时长」，不是「各镜均衡」**（v3 所写的"不支持悬殊切分"系技术侧推断，已撤回）。**11 + 2 + 2 完全合法。**

#### 时长校验规则（可直接写成公式）

| 项 | 数值 | 性质 | 校验动作 |
|---|---|---|---|
| 单镜硬下限 | **1.5s** | 硬约束（低于此模型帧数不够） | `<1.5` 报错 |
| 设计下限 | **2.0s** | 建议（勿用硬下限做设计值） | `<2` 告警 |
| **承载信息镜** | **≥3.0s** | 建议（低于此"立不住内容"） | 该镜含关键信息时 `<3` 告警 |
| 切点密度 | **约每 3 秒一切** | 建议 | — |
| **比值上限** | **最长镜 ≤ 最短镜 × 2.5** | 【推断】由 2–5s 推荐区间导出 | 超过告警 |
| 镜数代价 | **镜越多，跨镜不一致风险越高** | 官方提示 | 15 秒建议 **≤4 镜** |

#### 范式表

| 范式 | 镜数 | 时长分配 | 功能分工 | 适用场景 |
|---|---|---|---|---|
| **标准（默认）** | 3 | 5.0 / 5.0 / 5.0 | 入 / 主 / 出 | 通用 |
| 重主 | 3 | 7.0 / 4.0 / 4.0 | 入 / 主 / 出 | 需强主镜；比值 1.75 ✓ |
| 🔵 **对话（推荐）** | **4** | **4.0 / 3.5 / 4.0 / 3.5** | **A 说 / B 说 / A 说 / 反应** | 🔵 **正反打首选**——满足"一镜一说话人"，且每镜 ≥3s、切点 ≈3.5s 贴合密度建议 |
| 对话（长对白） | 2 | 7.5 / 7.5 | A 角 / B 角 | 单句较长时。⚠️ **7.5s 超出 2–5s 推荐区间**，仅在台词确实需要时用 |
| 快切 | 4 | 4.0 / 4.0 / 4.0 / 3.0 | 建 / 冲 / 爆 / 卡 | 打斗、爽点、密集信息 |
| 非对称（合法） | 3 | 9.0 / 3.0 / 3.0 | 入 / 主 / 出 | 比值 3.0 ✗ 超限，不建议 |
| 极限（合法不推荐） | 3 | 11.0 / 2.0 / 2.0 | 入 / 主 / 出 | 🔵 **合法但不宜**：两个 2s 镜低于"承载信息"的 3s 线，只能做纯衔接；且切点密度远低于每 3 秒建议 |

约束：
- 时长取 **0.5s 网格**；按上表校验规则自检。
- 🟢 **主次关系不靠时长**（见 §2.1 修正二）：即便三镜等长，也可靠信息密度 / 景别 / 运镜区分。
- 🟢 **正反打解禁**：仅限**单次请求内**。跨请求仍为硬阻断（见 §2.3 #11）。
- 🔵 **一镜一个说话人**：*"If two people need to talk, cut between them"*。两人对话必须切镜，不可在同一镜内让两人先后说话。这是对话段采用 4 镜而非 2 镜的直接原因。
- 🔵 **时长是目标值不是保证值**：时间戳为软引导，官方实测偏差 **≤0.12s**。**每段预留 0.2s 剪辑冗余，且不跨段累积**（总时长由请求固定，切点偏移只在段内重新分配）。
- 🔵 **不要在提示词里指定精确帧数或 FPS**——时机由模型控制。分镜表的时间码是**规划值**，不进提示词。

> **关于对话段的取舍**：v3 我给的是 2 镜 7.5/7.5，现在改为 4 镜。原因是两条官方约束叠加后 2 镜站不住——① 一镜一说话人要求来回切，2 镜只能切一次；② 7.5s 超出 2–5s 推荐区间。4 镜方案同时满足两条，且多出的"反应镜"在短剧里本就是情绪落点。

#### 生成策略：单次请求（方案 A）为默认，但必须配降级梯

技术侧曾提出 A（单次请求三镜）与 B（三次请求保 11s 主镜）二选一并倾向 A。**我的判断是 A**。🔵 技术侧后来撤回了"各镜须均衡"的说法（11+2+2 其实合法），所以 A 不再是被约束逼出来的唯一解——但**我仍推荐 A，理由换了**：
- **一致性**：A 把段内一致性从**提示词工程**变成**模型架构自带**（共享上下文），量产阶段省的是返工成本而非生成成本；
- **切点密度**：官方建议约每 3 秒一切，而 11s 不切远低于该建议。短剧常规镜长本就是 2–5 秒，5/5/5 比 11/2/2 更贴合格式规律；
- **信息承载**：11/2/2 里的两个 2s 镜低于"承载信息"的 3s 线，只能做纯衔接，等于把 15 秒的信息量全压在 11 秒里。

即：**11+2+2 合法但不好用**，A（均衡多镜）是选择而非被迫。

**但 A 有一个技术侧与 team-lead 都未提及的真实代价：丧失选择性重生成能力。** 单次请求出三镜，若第 2 镜出现手部崩坏，重生成会把第 1、3 镜一起重抽——你可能修好了一个镜头，同时弄坏了两个。**这在量产阶段是成本事故。**

因此不采用"A 或 B"，而采用 **A 为默认 + 三级降级梯**：

| 层级 | 做法 | 使用时机 | 一致性 |
|---|---|---|---|
| **T1 默认** | **单次请求 2–4 镜**，时间戳切分 | 首次生成 | 最好，模型内部保证 |
| **T2 单镜重生成** | 仅重生成失败镜，**首帧 = 前镜尾帧，尾帧 = 后镜首帧**（FL2VA） | 三镜中 ≤2 镜不合格 | 高，两端被帧锁定 |
| **T3 全拆** | 三镜各自独立生成，FL2VA 串联 | T2 反复失败 | 中，需锚点工程兜底 |

> 🟢 **FL2VA 与多镜不是替代关系，是互补关系**：多镜负责"首次生成的一致性"，FL2VA 负责"局部返修的一致性"。正是 FL2VA 的存在，才让 T2 这一级成为可能——**没有 FL2VA，A 方案的返修只能走 T3，那 A 就不该做默认**。这是本次规格更正带来的最大结构性收益。

#### T1 的前置要求（否则降级梯失效）

T1 生成时，**每一镜的提示词必须自成一体**——完整写出角色、服装、环境、光线、画风，不得依赖"共享上下文"省略。原因：一旦需要走 T2，该镜要被单独抽出重生成，缺字段的提示词会直接崩。

> 这条是纯流程约束，成本是提示词变长（H3 上限 7,000 字符，不构成问题），收益是保留逃生通道。**禁止为了省 token 而让后两镜的提示词依赖前文。**

#### 成本参考（供 team-lead 测算）

H3 一条 15 秒 2K ≈ **$1.95**。120s/集 = 8 单元 = **$15.6/集**；60 集 ≈ **$936**；按 2.5× 返工系数 ≈ **$2,340 / 60 集**。若按 §1.1 估算的 100–160 集（100 万字网文），全剧生成成本约 **$4,000–6,200**。此为主要变动成本，不含人工与存储。

### 2.3 衔接镜头类型库（10 种，含技术侧风险评级）

风险列由 h3-failcase-research 提供【技术侧】；`处置` 四值定义见 §3。

| # | 类型 | 适用情境 | 景别 | 运镜 | 与前后段对齐方式 | 风险 | 处置 |
|---|---|---|---|---|---|---|---|
| 1 | 空镜/环境氛围镜 | 段落首、时空切换 | 远景/全景 | 缓推或固定 | 延续前段色调与光源方向；下段主镜从此处"推入" | 低 | 无 |
| 2 | 手部特写 | **握拳**、手指覆布料 | 大特写 | 微推 | **动作顺接**：上段起势→本镜完成→下段接续 | 高 | 规避 |

#### #7 局部→整体揭示镜：解禁，但有一个新失效模式

FL2VA 解决了"终点构图崩"，但**没解决中间路径**：模型要在已知两端之间插值，**插值路径不受控**，中段仍可能出现身体比例畸变。失效模式从"终点崩"变为"中段畸变"。🔵 技术侧确认该风险真实存在（机制层面），但 **H3 上无公开实测数据**，标注【推断】。

**使用条件**（双重条件，缺一不可）：
- 拉远段 **≤3 秒** **且** **≤该镜时长的 50%**——真正决定插值难度的是相对比例而非绝对值（3s 在 5s 镜里占 60%，在 12s 镜里只占 25%）；
- **高 stakes 揭示（身份曝光、关键反转）仍走硬切**，不赌单次插值；
- 首帧局部图 + 尾帧全景图**必须先出图**，即新增资产类别：**首尾帧构图图**（见 §5.2）。

#### #11 正反打（新增）

### 2.4 匹配剪辑在 AI 生成中的可行性与写法

【业界】三类匹配剪辑：图形匹配、动作匹配、声音匹配。

| 类型 | AI 可行度 | 原因 | 提示词写法要点 |
|---|---|---|---|
| 图形匹配 | 🟢 **高**（恢复原判） | **FL2VA 可用**，可直接锁定终点帧 | 描述串写"圆形主体居中占画面 1/3，右侧暖色边缘光"；或直接给同一张构图参考图 |
| 动作匹配 | **中** | 方向可控，速度与幅度不可精确控制 | 只写"慢速、单一、单向"动作；用方括号运镜指令，见下 |
| 声音匹配 | 🟢 **高（且方式变了）** | H3 **原生生成音频**，与画面同一次推理；J-cut/L-cut 改为在提示词时间轴上排布，或由后期剪辑处理 | 上段尾部音效提前 0.3s 入，或延续至下段 |

**匹配三锚点**【推断】：① **色彩锚点**（同一光位/色温描述串）② **运动方向锚点**（上段出口方向 = 下段入口方向，严禁反向）③ **构图锚点**（末帧主体位置 ≈ 首帧主体位置）。

🟢 **锚点工程的作用范围已大幅缩小**：段内三镜由模型共享上下文自动维持，**三锚点只在"段与段之间"（跨请求）才需要人工写**；且该处可用 FL2VA 直接把上段尾帧作为下段首帧，比描述串对齐更可靠。三锚点从"每三段做一次"降为"每 15 秒做一次"，工作量约降为 1/3。

**重要提醒**：AI 生成是概率性的，匹配应做到"粗匹配"（形状/色彩/方向级），**不要追求像素级**。

#### 🟢 多镜结构化提示词【技术侧】

H3 支持**带时间戳的多镜结构化字段**，提示词上限 **7,000 字符**（v2 的"100 词上限"作废，该数据来自 2.3）。结构：

```
[Shot 1] <画面描述> <运镜> <台词/声音>
[Shot 2] At 00:05.000 → <同上>
[Shot 3] At 00:10.500 → <同上>
```

规则：
- 各镜时长由时间戳切分；🔵 约束为**每镜最短时长**（≥2s 设计值、承载信息镜 ≥3s）与**比值上限 ×2.5**，**非"均衡"**；
- 官方建议单条 clip 描述约 **20 英文词为舒适区、约 10 词/行**（此为**描述密度**建议，非硬上限）；
- **每镜提示词必须自成一体**（完整角色/环境/光线/画风），以保留 §2.2 的 T2 单镜重生成能力。

#### 🟢 运镜写法硬规则【技术侧】

**机制前提**：① **每镜只给 1 个运镜**（堆叠运镜 = 画面混乱漂移）；② H3 官方支持 15 个方括号运镜指令，显式指令比自然语言更准。

**15 个官方运镜 token**：`[Truck left] [Truck right] [Pan left] [Pan right] [Push in] [Pull out] [Pedestal up] [Pedestal down] [Tilt up] [Tilt down] [Zoom in] [Zoom out] [Shake] [Tracking shot] [Static shot]`
规则：**同一括号内最多 3 个 = 同时执行；写在提示词不同位置 = 顺序执行**。

**「运动方向锚点」四条硬规则**：
1. **两段必须用同一个指令 token**。上段末用 `[Truck right]`，下段首也必须是 `[Truck right]`。禁止同义改写（`pan right` / `move rightward` / `camera drifts right` 会走出不同速度与幅度，是"粗匹配也匹配不上"的主因）。
2. **方向句放在该镜描述的开头**，不要埋在场景描述之后。
3. **给两段一个共同物理参照物**：上段末 `...ending with a dark wall filling the entire frame`；下段首 `Starting with a dark wall filling the frame, the camera continues rightward to reveal...`。
4. 🟢 **左右方位：单次请求内已解决，跨请求仍是硬阻断**。同一次请求的多镜共享上下文，模型自动维持方位与 180°轴线；**但两次独立请求之间仍无法保证**，可靠手段只有：① 合并进同一次请求（首选）；② 用 FL2VA 把上段尾帧作为下段首帧（**新增手段，v2 时不可用**）；③ 后期水平镜像翻转。分镜表须写死——否则分镜师会反复用提示词尝试对齐左右，纯浪费。

**可直接套用的稳定器句式**（🟢 否定句按"每镜最多 1 句、置末尾、前须有正向状态描述"执行）

```
【通用稳定器】Locked-off camera on a tripod, single continuous camera move, constant speed
from start to finish, no acceleration, no deceleration, no direction reversal, no camera shake,
no jitter, no stutter, no frame flicker, stable exposure throughout.

【末帧抖动专项】The camera settles and holds completely still for the final second,
ending on a stable held frame with no drift.

【方向连续性】[Truck right] — the camera moves continuously from left to right in one
unbroken move, maintaining the same speed and the same direction, never pausing and never reversing.

【纵深推拉】A single slow push-in at a constant rate, no zoom, no handheld wobble,
the subject stays centered in frame throughout.
```

### 🔴 风险四列枚举定义【技术侧提供，已采纳】

| 列 | 类型 | 枚举值 |
|---|---|---|
| `风险类型` | 单选 | **9 码定稿**：`H` 手部异常 / `B` 肢体与人体结构 / `M` 镜头运动 / `I` 身份漂移 / `T` 文字与屏幕 / `P` 物理与空间 / `A` 小物件资产丢失 / `X` 跨镜头一致性 / 🔵 **`V` 语音与说话人** |

| `处置动作` | 单选 | 规避 / 降级 / 后置 / 硬阻断 |
| `备选方案` | 文本 | 必填；`处置动作` = 硬阻断时**强制非空** |

**`处置动作` 四值定义**：
- **规避** — 改镜头设计本身（例：签字特写 → 合上文件）
- **降级** — 镜头保留，但不承载关键叙事信息（例：手机屏只发冷白光，不留内容）
- **后置** — 生成照做，问题留到后期/剪辑/合成解决（例：屏幕内容后期贴、左右方位后期镜像）
- **硬阻断** — **提示词解决不了，必须靠后期或换工具**。这一档是给客户看的"我们承认这里做不到"

**🟢 硬阻断项从 5 类缩减为 3 类**（H3 能力更正后）：

| v2 的硬阻断 | H3 上的新判定 |
|---|---|
| ① 可读文字 | 🔵 **部分解禁**。招牌/字幕类大字可用（官方"英文双引号逐字保留"写法）；**但手机屏小字维持高风险**（8-bit 量化第一受害者），未实测前不赌 |
| ② 跨生成左右方位一致 | **仍为硬阻断**（仅限跨请求）。单次请求内已由共享上下文解决；跨请求新增 FL2VA 手段 |
| ③ 跨生成 180°轴线（正反打） | **仍为硬阻断**（仅限跨请求）。单次请求内**完全可行**；🔵 对话段应走 **4 镜**方案，见 §2.2 |
| ④ 拉远揭示 | 🟢 **解禁** → 降为中。FL2VA 锁定终点构图；残余风险为"中段插值畸变"，见 §2.3 #7 |
| ⑤ 小物件纯文本复现 | **仍为硬阻断**。必须走参考图（FL2VA 不改变"纯文本≈放弃"这一结论） |
| — | 🟢 **口型同步不再是硬阻断**：H3 原生生成音频、自带唇形同步（支持 11 种语言，含中文） |
| — | 🔵 **台词修改不再是硬阻断**：H3 in-context 编辑支持 `dialogue replacement`，见 §4 |

#### 🔵 `保留强度` 枚举（6 值，H3 官方 `retention_analysis:` 字段）

| 标记 | 含义 | 用法 |
|---|---|---|
| `fully_preserved` | **完全保留**：身份、特征、道具全不变 | 脸、发型、核心服装、关键道具——**必用** |
| `partially_preserved` | 部分保留 | 允许随情境微调的（外套开合、发型松散度） |
| `attribute_transfer` | **只迁移属性**（风格/材质/色彩/质感） | 画风参考、调色参考 |
| `weak_reference` | 弱参考，仅作倾向 | 氛围板、构图倾向 |
| `partially_copy` | 音频轨复用 | BGM 复用 |
| `reference` | 音色参考 | 角色音色 |

**两条铁律**：
1. **承载身份识别的资产一律 `fully_preserved`**——官方原话：*"A marker of `fully_preserved` on a face is what keeps it the same face all the way through."*
2. **纯风格/氛围一律 `attribute_transfer`**——风格参考若误用 `fully_preserved`，模型会把参考图里的物体也搬进画面。

## 4. 语速与时长换算（v3 修订：原生音频改变了本表的性质）

🟢 **H3 原生生成音频并与画面同一次推理，自带唇形同步**。这带来一个根本变化：

> **语速不再是"可配置参数"，而是"模型的输出行为"。** 本表从"配音工程配置表"变为**时长校验表**——用来判断写好的台词能不能塞进既定镜长，以及在模型语速偏离时留出多少余量。

**换算公式**（用途不变）

```
镜头/段落时长  T = 台词字数 W ÷ 语速 V ÷ 台词占用率 ρ
（ρ 取 0.70；V 取 4.5 → 简化式：T ≈ W ÷ 3.15）
台词字数上限  W_max = T × V × ρ
```

**语速档位**（V 用于校验，非配置）

| 档位 | 字/分 | 字/秒 | 说明 |
|---|---|---|---|
| 慢速（情感/悬疑铺垫） | 180–220 | 3.0–3.7 | 悬念制造、情绪旁白 |
| 中速（通用口播） | 260–280 | 4.3–4.7 | 短剧对白默认档 |
| 快速（冲突爆发） | 340 | 5.7 | 争吵、爽点爆发句 |
| **校验基准** | 270 | **4.5** | 【业界】2026 年一线投放样本（400+ 条）：**4.3–4.8 字/秒** 完播率最优，低于 3.5 字/秒前 3 秒易被划走 |

**单镜台词容量表**（ρ=0.70，V=4.5）

| 镜长 | 建议上限 | 对应范式 |
|---|---|---|
| 3.0s | 9 字 | 四镜快切 / 短反应镜 |
| 3.5s | 11 字 | 🔵 四镜对话 |
| 4.0s | 13 字 | 🔵 四镜对话 / 快切 |
| **5.0s** | **16 字** | 三镜标准（默认） |
| 7.0s | 22 字 | 三镜重主 |
| 7.5s | 24 字 | 双镜长对白 |

**单元总量**：15s × 4.5 × 0.70 = **47 字**。🟢 采纳技术侧"留 30% 余量"的建议，取 **≤45 字/单元**。

> 🔵 **交叉验证已完成，45 字定稿**。技术侧引官方原文确认"约 20 英文词"**确指台词容量**（原文：*"Around twenty words fit comfortably in a clip, about ten to a line; pack in more and the delivery rushes, then slurs"*——"delivery rushes, then slurs"只能形容口语）。两条独立路径收敛：
> - 我的：15s × 4.5 字/秒 × 0.70 = **47 字**
> - 官方折算：15s × **2.5 词/秒**（官方语速基准）× 0.70 ≈ 26 英文词 → 中文同占用率 = **47 字**
>
> → **定稿 ≤45 汉字/15 秒单元，可写入模板。** 顺带确认：v3 担心的"20 词与提示词长度冲突"不存在，我的"每镜自成一体"要求不受任何约束。

> ⚠️ **口径澄清（2026-08-30 修订）**：上面「两条独立路径收敛」收敛的是 **47**，不是 45。
>
> | 档 | 值 | 性质 |
> |---|---|---|
> | 理论天花板 | **47 字** | 两条路径同解，有官方支撑 |
> | 工程定稿 | **≤45 字** | **仅比 47 少约 4%**，是安全边，**非推导值**，不得宣称有官方依据 |
> | 写作目标 | **38 字**（区间 30–40） | 官方舒适值 20 词/10s 折算到 15 秒：2.0 词/秒 ≡ 3.6 字/秒 → 15 × 3.6 × 0.70 |
>
> 另：官方原句 "A **10-second clip** fits maybe 20-25 spoken words" 说的是 **10 秒**。早期曾把 20 词直接 ×1.8 得 36 字（漏了 10s→15s 换算），**正确值是 38 字**。

**结论（v4）**：
- 15 秒单元台词 **建议 30–40 字（官方推导值 38）**，硬红线 47 字，工程定稿 **≤45 字**——收紧到 45 是因为**我们不再能控制模型实际语速**，必须留工程安全边；
- 单镜按上表分配，**入镜与出镜尽量无台词或 ≤8 字**（纯音效/空镜更稳）；
- 🔵 **一镜一个说话人**：官方 *"If two people need to talk, cut between them"*。同一镜内不得让两人先后说话——**这是对话段采用 4 镜方案的直接原因**；
- 【业界】字幕单行 12–15 字，断句对齐换气点，字幕比语音早 0.2s 结束；字幕仍为后期叠加。

### 🟢/🔵 原生音频带来的流程变更（v4 修订）

**1. 🔵 「音频锁」审批流程——撤销，不要加。**
H3 支持 in-context 视频编辑，其中包含 **`dialogue replacement`（对白替换）**，官方明确"未指定的镜头元素保持原样"。即：**改一句台词 ≠ 重生成整个镜头**，走编辑模式只改对白、画面保留。
> 两点注意：① 这是**视频编辑模式**（需上传源片作参考），不是"只重生音轨"的参数开关；② 画面是否逐帧 100% 不变**未经独立实测**，官方表述为"未指定元素保持不变"。**建议样片阶段跑一次验证再写进 SOP。**
> → 客户流程维持宽松，**无需加台词变更审批环节**。

**2. 说话人串音 / 语种串台是真实高频翻车项**（风险类型码 `V`）。
防护措施：说话人 ID **全剧稳定、跨镜跨集不重编号**（重编号即串音）；加语种标签 `[Chinese]`；台词放 **`<d>` 标签**内逐字保留，**不加英文双引号**（双引号在官方语义里专属「画面内可见文字」，套用会诱导演成画面字幕）；说话人描述放在标签**外**。H3 唇形同步支持 11 种语言（含中文）。

> ⚠️ 存在一处官方口径冲突：MiniMax × ComfyUI 官方直播建议"用引号写出台词放进镜头描述"，与官方 `base-en.txt` 的示例（`<d>` 内无引号）不一致。**默认遵守 `base-en.txt`**；若用直播那条技巧，引号只写在镜头描述里，不要写进 `<d>` 内。已标【待验证】。

**3. 口型同步不再是风险项**，但**语速失控**成为新风险：模型可能说得过快（塞得进但听不清）或过慢（塞不进被截断）。缓解：按 30–40 字写，留 20–30% 余量；样片阶段实测模型实际语速并回填本表 V 值。

## 5. 角色卡与资产一致性管理

### 5.1 角色卡字段清单

【业界】人设卡万能公式：**年龄 + 身份 + 外貌特征 + 固定穿搭 + 专属小动作 + 统一画风**。拆解为可执行字段：

| 组 | 字段 |
|---|---|
| 基础 | 角色ID、姓名/代称、年龄、性别、身份 |
| 外观（逐项写死） | 脸型、发型发色、瞳色、肤色、五官特征、体型、标志性表情 |
| 固定穿搭 | 上装/下装/鞋/外套（每套一个**服装版本ID**，换装即换 ID） |
| 行为锚点 | 专属小动作（推眼镜、捏衣角、抿唇）、口头禅/称呼习惯 |
| 画风 | 统一画风标签串（每段提示词原样复用） |
| 声音 | 音色 voice_id、语速 V、情绪基线 |
| 参考图集 | 正面定妆图、侧面、全身、表情集 4–6 张（含 ID） |
| 提示词模板 | 一段**可直接复制、token 级不变**的标准描述串 |

### 5.2 人物资产表

| 字段 | 说明 |
|---|---|
| 资产ID / 名称 / 所属角色 | `AS_07 银色耳环 → CH_01` |
| 类别 | 随身佩戴 / 道具 / 场景固定物 / 身体标记 / 特效 / 🟢 **首尾帧构图图** |
| | 🟢 首尾帧构图图：揭示镜、同构图匹配镜等需先渲出端点构图图再生成视频，属新增资产类型 |
| 外观描述串 | 固定不变，提示词中逐字复用 |
| 出现集段清单 | 便于批量预生成与复用 |
| 🔴 **是否出参考图** | **必填。填"否"的资产一律自动降级为"不承载叙事信息"**【技术侧】 |
| 参考图 ID | 指向资产库；小物件**必须**出参考图 |
| 🔵 **保留强度** | 每个参考文件单独指定，枚举 6 值（见 §3）。**承载身份识别 → `fully_preserved`；纯风格/氛围 → `attribute_transfer`** |
| 一致性风险等级 | 见下方**修正后的分级** |

**🔴 风险分级修正**【技术侧】：原分级把"义肢"与"耳环"并列为高，**这是错的**。义肢不只是小物件，它会改变**肢体轮廓与关节结构**，模型极易渲染成正常肢体或与身体融合成畸形——属"肢体结构崩坏"而非"物件丢失"，是跨类别风险（对应风险类型码 `B` 而非 `A`）。

**修正后分级**：**义肢（最高，建议直接禁用，或只在静态中远景出现）＞ 纹身（高，随身体变形而形变）＞ 耳环/戒指（中高）＞ 手表/手机（中）＞ 大面积衣物/围巾/外套（低）**

> 🔴 **比类别分级更可执行的判据**【技术侧】：真正决定成败的不是物件类别，而是三个变量——
> ① **有没有参考图**（决定变量，非加分项：移除视觉锚定后一致性得分从 7.99 崩到 0.55）；
> ② **物件是否在运动中**（静止画面测出的成功率无意义，静止时耳环当然不掉）；
> ③ **同时锁了几个**（业界一致建议 **one or two immutable accessories**，只锁 1–2 个，不要多锁）。
> 因此资产表以 `是否出参考图` 为主判据，类别分级仅作参考。

### 5.3 一致性三锁与降级策略

1. **参考图锁**：同一角色/资产全程复用同一组参考图（I2VA / 🟢 FL2VA）。
2. **描述串锁**：角色与资产的描述串做成模板常量，禁止临场改写、禁止同义替换。
3. **参数锁**：固定种子、画幅、风格权重，改一处即全量重测。
4. 🟢 **强度锁**（新增）：参考资产的 `保留强度` 标记随资产表固定，**不在分镜阶段临时改**。身份类资产一律 `fully_preserved`，风格类一律 `attribute_transfer`。

> 🔵 v4 说明：v3 曾列"声音锁"（台词定稿审批），**已撤销**——H3 支持 `dialogue replacement`，改词不必重生成画面，见 §4。

> 🟢 **三锁的作用范围因多镜生成而收窄**：段内一致性已由共享上下文保证，三锁主要服务于**跨段、跨集**的一致性。这不降低三锁的重要性——跨集一致性恰恰是长篇项目最难的部分——但意味着**三锁应重点加固在"跨请求边界"上**：段与段的接缝处、换装点、时间跳跃点。

**⚠️ 关于"小物件复现成功率"的证伪说明**：方向已证实（多来源记录眼镜/珠宝/纹身跨帧消失与重现；机制为像素占比过低导致交叉注意力不足，叠加"跨帧状态跟踪弱"），但**没有任何公开的量化基准**给出"耳环 = X%"这类数字。网上流传的"某模型珠宝保真度优异"均来自聚合站/营销站软文，无方法论、无可复现测试集，**判定为不可引用，本报告不引用任何此类百分比**。

**自建测试集规范（修订版）**【技术侧建议】：
- **样本量 ≥20 次**（原定 10 次偏少）：4 次/镜 × 5 个不同镜头类型；
- **必须在真实运动条件下测**——静止画面测出的成功率无意义；
- 登记指标并沿用业界术语：**PPR（Prop Persistence Rate）** 与 **WLR（Wardrobe Lock Rate）**，目标 ≥80%；
- **分级处置，不要一刀切**：**≥90%** 可承载叙事；**70–90%** 可出场但不承载关键识别信息；**<70%** 只在静态近景出现或直接砍掉。
